# 개인정보 학습 데이터 가이드 (고정 라벨)

목표: 모델이 정책 규칙과 별개로 **항상 켜진 개인정보 라벨 3개**를 정확히 잡게 한다.
정의는 `fixed_labels.json`. 정형 개인정보(주민번호·전화·이메일·카드·계좌)는 규칙 엔진 담당이라 넣지 않는다.

⚠️ 평가 데이터는 열지 않는다: `eval.jsonl`, `eval_v2.jsonl`, `eval_raw/`, `EVAL_GUIDE.md`.

## 1. 구간 기준

| ID | 표시 | 표시하지 않음 |
|---|---|---|
| P-NAME | 이름만: `김지훈 책임` → `김지훈`, `지훈 님` → `지훈`, `김 대리` → `김`, `Daniel Park` | 직함·호칭·님·씨, 조사 |
| P-ADDR | 주소 구절 전체: `서울시 마포구 월드컵북로4길 17, 3층`, `B동 1203호`, `성남시 분당구 정자동 178-4` | `부산 출장`, `강남역 근처`, `판교 사옥`처럼 찾아갈 수 없는 지명 |
| P-SENS | 특정 개인의 민감한 사실을 담은 절: `우울증 치료로 휴직 중`, `작년에 음주운전으로 벌금형`, `감봉 1개월 징계` | 일반론("우울증 초기 증상"), 통계, 본인이 특정되지 않는 이야기 |

- P-SENS 범위: 건강·질병·치료·수술·임신, 정신건강·상담, 징계·형사 처벌·범죄 경력, 종교, 정치 성향, 노조 가입
- 인사평가 등급·저성과자 지정은 P-SENS가 **아니다**
- 같은 구간이 회사 기밀 규칙에도 해당하면 같은 문자열을 두 번 적는다: `[["감봉 1개월 징계", "R07"], ["감봉 1개월 징계", "P-SENS"]]`
- 조사는 구간 밖. 구간 문자열은 원문에 글자 그대로

## 2. 반드시 넣을 함정 (음성, 표시하지 않음)

v1 모델이 실제로 틀린 유형이다. 함정 문장 비중을 40% 이상으로 한다.

- 이름이 아닌 것:
  - 코드명·제품명 (`블루웨일`, `은빛여우`, `온새미로`)
  - 직함·역할 (`플랫폼팀장`, `헤드헌터`, `담당 PM`)
  - 회사·브랜드 (`하늘소프트`, `민준카페`)
  - 일반 단어 (`한결같이`, `이슬비`, `하늘이 맑다`)
- 주소가 아닌 것:
  - URL (`https://wiki.corp.xxx.local/hr`), IP·포트 (`10.20.4.15:8929`)
  - 내부 경로, 이메일 도메인
  - 지명만 있는 표현 (`대전 지사`, `김포 센터`, `성수동 카페`)
- 민감정보가 아닌 것:
  - 일반 건강 상식, 의료 제도 질문
  - 종교·정치 일반론
  - 공개된 판결 기사 요약

## 3. 이름 다양성 (P-NAME)

- 성 분포: 김 20%, 이 14%, 박 8%, 최·정·강·조·윤·장·임 등 나머지 고루. 복성(남궁·제갈·선우·황보) 3%
- 외자(`김솔`), 4글자, 외국인(영문·한글 표기) 10%, 일반 단어와 같은 이름(`한결`, `이슬`, `하늘`)이 사람인 문맥 10%
- 형태: 성+이름+직함, 이름만, `~님/씨/이`(`지훈이가`), 성+직함, 한 문장에 여러 명, 목록·표 조각
- 실존 인물 금지. 공인이 등장하는 문맥(`OO시 시장 홍길동`이 아니라 지어낸 이름)도 표시한다

## 4. 회사 기밀과 섞기

문장의 30%는 `rule_bank.json`의 기밀 규칙 구간도 함께 넣는다 (예: `조현우 팀장 연봉 6,100으로 확정` → 이름 + R08).
이때 `GUIDE.md` 1절의 금지 개념(이사회, 결함·리콜, 고객 해지, 임원 일정, 가격 인상, 미발표 실험 결과, NDA 사양, 장애 분석)은 쓰지 않는다.

## 5. 출력과 검사

- 형식: `GUIDE.md` 4절과 같다. `{"text", "spans": [["구간", "ID"]], "near": [...]}`
  - 음성 문장의 `near`에는 헷갈리는 고정 라벨 ID를 적는다 (예: `["P-NAME"]`)
- 다 쓰면 `python3 data/check_raw.py <파일>` 로 오류 0

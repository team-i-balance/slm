# 기밀 구간 탐지 SLM

목표: 사내 서버(맥북 M5급 CPU)에서 문장당 100ms 이하, 모델 300MB 이하.
SLM은 기밀 정보만 맡는다 (개인정보는 `../piiguard` 규칙 엔진 담당).
규칙 = "무엇을 기밀로 보는지" 설명. 새 규칙은 재학습 없이 적용되는 것이 목표.

- `data/rules.json` — 가상 회사 모아랩스 규칙 30개 (train 22 / heldout 8: 학습 금지)
- `data/eval.jsonl` — 평가 104문장, 정답 구간 90개, 기밀 없는 문장 30개(함정 포함)
- `evaluate.py` — 재현율(학습 규칙/처음 보는 규칙), 정밀도, 오탐 문장률, 지연

```bash
uv venv --python 3.11 .venv && uv pip install --python .venv/bin/python torch gliner sentencepiece protobuf tiktoken python-mecab-ko accelerate
.venv/bin/python evaluate.py --model gliner --threshold 0.25          # 기성 모델
.venv/bin/python build_dataset.py                                     # data/train_raw → train/dev.jsonl
.venv/bin/python train.py --out models/v1 --steps 1200                # 미세조정 (M5 MPS 약 40분)
.venv/bin/python evaluate.py --model gliner --name models/v1/final --threshold 0.3
```

## 기준 측정 (2026-11-05, 학습 없음, CPU)

| gliner_multi-v2.1, 이름+설명 | 0% | 0% | 0% | - | 0% | 300ms |

해석
- 기성 GLiNER는 '사람/회사' 같은 개체명용이라, "영업이익 87억" 같은 **의미형 기밀 구절을 거의 못 잡음** → 미세조정 필수
- 설명을 라벨로 넣으면 0% — 긴 라벨로 학습된 적이 없음. 설명을 쓰려면 그렇게 학습시켜야 함
- 속도는 이미 목표 이내 (규칙 30개 동시 72ms)
- 2.89억 파라미터 중 **1.92억(66%)이 25만 단어 임베딩** → 한국어·영어 어휘만 남기면 약 1.2억, INT8로 약 120MB 예상

### 등급 판정 (`SlmDetector.judge`)

모델은 '어느 구간이 어느 규칙에 해당하는지'만 찾고, 등급은 보안팀이 정책에 정한 규칙 grade 중 가장 높은 것(C > S > O).
별도 분류 모델·생성형 LLM 대신 이 방식을 쓴 이유: 근거 구간이 남아 설명 가능, 같은 입력 같은 결과, 추가 지연·용량 0, FigJam 의 '서명된 정책 번들 → 등급 판정' 구조와 일치.
`detection_confidence` 는 backend `app/rules.md` 와 같은 high / medium / low (등급을 정한 구간 점수 0.7 이상이면 high).

### ONNX INT8 재현율 0% 원인과 수정

- 비양자화 `model.onnx`는 PyTorch와 점수가 같다 → 변환 문제가 아니라 **양자화 문제**
- GLiNER `export_to_onnx(quantize=True)`는 `quantize_dynamic(weight_type=QUInt8)`을 쓰는데, 이 모델에서는 부호 없는 8비트 가중치가 점수를 무너뜨린다(dev 60문장에서 fp32 대비 구간 일치 11%, v2 평가셋 재현율 0%)
- **QInt8(부호 있음)·채널별 양자화**면 구간 일치 92%. `export_onnx.py`가 이렇게 만든다(190MB). 불러온 뒤 `words_splitter`를 `EojeolSplitter`로 바꿔야 한다
- INT8은 점수가 조금 낮게 나와 **기준값 0.40 / 0.30**에서 fp32(0.45/0.35)와 비슷하다. `evaluate.py --onnx model_quantized.onnx`

| v3.1 INT8 (0.40/0.30) | 기밀 재현율 | 개인정보 재현율 | 오탐 문장률 |
|---|---|---|---|
| v2 평가셋 | 92.4% | 98.0% | 7.1% |
| Codex 외부 | 97.1% | 93.5% | 25.0% |
| Kiro 외부 | 90.5% | 98.2% | 14.3% |
| 8개 업종 | 78.9% | 100% | 3.3% |

  | v3.1 축소본 | 416ms | 459ms | 1.56GB |

- **INT8은 보류한다.** 서버에서 탐지가 0건으로 나왔다. VNNI가 없는 x86에서 s8 MatMulInteger가 포화되는 문제로 추정한다. 속도 이득도 작다. `reduce_range` 버전은 서버에서 아직 검증하지 않았다.
- 되돌리려면 서버 `slm.conf`의 `LOCAL_SLM_MODEL_DIR`를 `~/models/slm-v2-trim`으로 바꾸고 재시작한다.
- 남은 약점은 다음과 같다.
  - 이름 앞 단어나 조사까지 구간에 넣는다(`담당 한지우`, `김민수의`).
  - 공시된 수치를 기밀로 잡는다.
  - 생성기 문자열(openpyxl)과 `ABC 신한`을 오탐한다. 백엔드 규칙으로 막아 두었다.
